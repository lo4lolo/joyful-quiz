# 분석실 (analyze.html)

> 아이들은 즐겁게 퀴즈를 풀고, 선생님은 깊이 있게 분석해요.

선생님이 저장한 퀴즈 기록 파일을 **이 브라우저 안에서만** 열어 분석하는 화면이에요. 정답·오답뿐 아니라 **어떻게 풀었는지**(빠르기, 다시 만난 문제, 게임 흐름, 회복, 게임 속 선택)와 모둠 협력까지 보여요. 서버로 아무것도 보내지 않아요.

## 화면 구성
| 구역 | 보여 주는 것 |
|---|---|
| 기록 열기 | 📂 파일 열기(.json, 여러 개) · 끌어다 놓기 · 📁 연결한 폴더에서 불러오기 · 🧪 예시 기록 · 저장 못 한 임시 기록 복구 |
| 열린 기록 | 기록별 체크(분석에 넣기/빼기), 날짜·게임 방식·단원, 엑셀 저장·인쇄·기록 합치기 저장 |
| 한눈에 | 참여 학생, 문항 수, 전체 정답률, 평균 응답 시간, 응답 수 |
| 다시 가르칠 문제 TOP 3 | 정답률 낮은 문제(응답 3개 이상, 80% 미만) + 많이 고른 오답, 그 밖의 오개념 후보 |
| 문항 분석 | 문제별 정답률 막대(낮은 순/번호 순), 오개념 후보(한 오답에 응답 25% 이상), 평균 시간. 줄을 누르면 답 분포·해설·마지막 답이 틀린 학생 |
| 학생 분석 | 도움이 필요한 학생(정답률 60% 미만), 도전 과제를 줄 학생(85% 이상 + 반 중간값보다 빠름), 정답률×속도 산점도, 학생표. 이름을 누르면 문제별 답 |
| 학생×문항 | O(맞음)/X(틀림)/-(안 풂) 표. 여러 번 푼 문제는 마지막 답 기준, 섞여 있으면 `맞은/푼` 횟수 |
| 차시 비교 | 기록이 2개 이상일 때: 기록별 정답률 막대, 같은 문제의 처음→마지막 변화, 많이 나아진 학생 |
| 🎮 게임 속 학습 행동 | 해석 카드(짧은 해석 + 🧑‍🏫 수업에 쓰는 법) / 속도×정확도 4분면(반 전체, 빠르게 틀림 30% 넘는 학생·문제) / 다시 만난 문제(처음 vs 다시, 다시 만나서 맞힌 문제) / 게임 흐름(초반·중반·후반, 후반 15%p 넘게 떨어진 학생) / 틀린 뒤 회복·최장 연속 정답 / 건너뜀·문제 모양별·기기별 / 게임별 행동 카드 / 학생별 표(4분면 막대, 다시 맞힘, 초반→후반, 틀린 뒤, 최장 연속, 건너뜀, 살펴볼 점) |
| 🤝 모둠 협력 | 협력 기록(teams·events)이 있을 때만: 우리 반 목표 성공, 모둠 균형 지수 평균, 살펴볼 모둠원, 교사 알림·도착 지연 / 모둠 카드(균형 지수, 가장 큰 몫, 기여 0명, 모둠원별 몫 막대와 15%·50% 기준선, 공동 진행 횟수·평균 함께한 인원, 도움 준/받은, 작전·거절, 역할 맡은 모둠원, 성찰) / 성찰 분포(반·모둠) / 알림 종류별 건수·찾아감·평균 도착 |
| 🤖 AI 도움 | 프롬프트 6종(다음 차시 수업 설계 / 오개념 바로잡기 / 보충·심화 문제(엑셀 6칸 형식) / 학부모·학생 피드백 / 게임 속 학습 행동 돌아보기 / 모둠 협력 돌아보기*) → 📋 복사. *협력 기록이 있을 때만, 이름 없이 모둠 통계만 |
| 수업 설계 도우미 | 골든벨(진단) → 보물 상자(연습) → 카트 레이스·땅따먹기(복습) → 분석실 |

- 여러 기록은 **학생 이름**(띄어쓰기 무시)과 **문제 글자**(띄어쓰기·문장부호 무시)로 합쳐요.
- `🙈 이름 가리기`: 화면에 띄울 때 이름을 학생 A, B…로 바꿔요.
- `analyze.html?from=last`: 선생님 화면이 `localStorage.jq_last_record`에 넣어 둔 방금 끝난 기록을 자동으로 열어요.

## 게임 속 학습 행동 계산 (stats.js `behaviorAnalysis` · `behaviorInsights` · `behaviorSheetRows`)
- 답마다 `try`(이 게임에서 이 문제를 몇 번째 만났나) · `seq`(학생의 몇 번째 답) · `streak`(직전 연속 정답) · `skip`(시간 초과·모르겠어요) · `kind`(학생에게 보인 모양) · `dev`(t 태블릿 / p 컴퓨터). **예전 기록**은 시간 순서로 try·seq·streak 를 채우고, 빈 답을 건너뜀으로, 문제의 kind 를 써요 (dev 는 없음).
- **4분면**: 문제마다 중간 응답 시간(건너뜀 제외) 이하면 빠름. 빠르고 정확(숙달) · 느리지만 정확(신중) · 느리고 틀림(어려움) · 빠르게 틀림(찍기·성급 의심). 답 5개 이상이고 빠르게 틀림 ≥ 30% 면 표시 (`BEHAV.fastWrong`).
- **다시 만난 문제**: try=1 정답률 vs try≥2 정답률(재도전 향상 %p), 처음 틀린 (학생·문제) 가운데 뒤에 맞힌 것 = 다시 만나서 맞힘.
- **게임 흐름**: 학생·기록마다 답 순서를 셋으로(답 6개 이상). 초반·중반 정답률 − 후반 정답률 ≥ 15%p 이고 후반 답 3개 이상이면 ‘후반 지침’ (`BEHAV.fatigueDrop`).
- **틀린 뒤 회복**: 틀린 바로 다음 답의 정답률 vs 맞힌 다음 vs 전체, 가장 긴 연속 정답.
- **게임별**: `caught`(도깨비에게 잡힌 말 `by:'dokkaebi'` 제외) · `chest.risky` 비율 · `buy`(첫 구매까지 걸린 초 중간값, 물건 섞임) · `reel.quality` · `claim.enemy`(공격)/확장 · `item.kind` · `duel`(승패·정답·중간 시간) · `choice.route` short/long(윷).
- 해석 문장은 아이를 단정하지 않는 말로 쓰고, ‘살펴볼 점’은 말 걸기의 실마리로만 써요.

## 모둠 협력 계산 (stats.js `coopSession` · `coopAnalysis`, docs/COOP_DESIGN.md)
- 기여: 순위의 `extra.contrib`(공동 진행에 쓰인 정답) — 없으면 정답 수로 대신해요. 몫 = 기여 ÷ 모둠 기여 합.
- **기여 적음** 몫 < 0.15 (모둠 2명 이상), **독주** 몫 ≥ 0.5 (모둠 3명 이상), **기여 0명** 기여 0. 기준은 `COOP` 로 바꿀 수 있어요.
- **균형 지수** = 1 − 지니(모둠원 기여). 1 = 모두 같음.
- 공동 진행: `shared` 이벤트 수와 `data.distinct` 평균(필요 인원 `need`/`all`). 도움: `help` 준 모둠(`team`)·받은 모둠(`data.toTeam`). 작전: `choice` 의 `route`·`refused`. 역할: `role` 을 맡은 서로 다른 모둠원 수.
- 우리 반 목표: 순위 `extra.classWin`, 없으면 `classGoal` 이벤트. 성찰: 학생마다 마지막 `reflect.v`(great·good·little·next).
- 교사 알림: `alert.data.kind`(stuck·fail·lowShare·dominance) 건수, `teacher`(visit) 의 `delay` 평균 = 알림 → 교사 도착.
- 예전 기록(teams·events 없음)은 이 칸이 숨겨지고 나머지 분석은 그대로예요.

## 파일
- 기록 파일 형식은 `docs/ARCHITECTURE.md` '기록 파일' 참고. 이름: `즐거운퀴즈_<제목>_<YYYY-MM-DD_HHmm>.json` (+ `.xlsx`).
- 기록 묶음(기록 합치기 저장): `{ app:'joyful-quiz', v:1, kind:'bundle', savedAt, sessions:[기록…] }`
- 엑셀 시트: 요약 · 문항분석 · 학생분석 · 학생x문항 · (차시비교) · 학습행동 · (모둠협력) · 응답원자료 · 숨김 `_기록원본`(기록 JSON). 숨김 시트 덕분에 이 앱이 만든 .xlsx 도 분석실에서 다시 열 수 있어요.
- 코드: `public/js/record.js`(만들기·저장·읽기·임시 보관), `public/js/stats.js`(통계, DOM 없음), `public/js/analyze.js`, `public/css/analyze.css`, 예시 `public/samples/sample-record-1.json`, `-2.json`, `-3.json`, `-4.json`(5학년 과학 '온도와 열', 24명: 골든벨 → 카트 레이스(서둘러 찍는 학생 2명·후반에 지치는 학생 2명·아이템 이벤트) → 다 함께 줄다리기 6모둠 → 퀴즈 부자(구매 이벤트). 모든 답에 try·seq·streak·kind·dev, 세 명 중 한 명은 태블릿. 3번에는 독주 1명(해치)·기여 0명 1명(백호)·교사 알림 5건이 들어 있어요).

## 개인정보
- 기록은 서버 디스크에 쓰지 않아요. 교사 브라우저가 모아서 교사 PC(연결한 폴더 또는 내려받기)에 저장해요.
- 분석실은 파일을 브라우저 안에서만 읽어요. 외부 주소·CDN 없음(CSP `script-src 'self'`). 예시 기록만 같은 서버의 `samples/`에서 읽어요.
- 게임 중 임시 기록은 교사 기기 localStorage(`jq_draft:live`)에만 있고 7일 지나면 지워져요.
- AI 프롬프트에는 기본으로 **반 전체 통계**만 넣고, 학생별 문구에서도 이름은 `학생 A`처럼 가명으로 바꿔요(가명 대조표는 화면에만). 실제 이름 넣기는 경고 후에만 켜져요.
- '게임 속 학습 행동 돌아보기' 프롬프트에는 반 전체 통계만 넣어요(학생 이름 없음).
- '모둠 협력 돌아보기' 프롬프트에는 학생 이름을 넣지 않아요(모둠 이름과 몫 통계만).
- 엑셀·JSON 파일에는 학생 이름이 들어 있으니 학교 밖으로 보내지 않아요.

## 시험하기
```
node --test tests/record.test.mjs     # buildRecord, fileBase, 검사, 통계, 학습 행동, 모둠 협력, 엑셀(있으면), 임시 보관
npm start → http://localhost:3030/analyze.html → '예시 기록으로 체험하기'
```
- 폴더 연결(File System Access API)은 크롬·엣지(컴퓨터)에서만 돼요. 다른 브라우저는 파일 열기/내려받기로 동작해요.
