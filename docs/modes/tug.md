# 🪢 다 함께 줄다리기 (`tug`)

우리 반 전체(모든 모둠)가 귀여운 도깨비 팀과 줄다리기를 한다. 각자 자기 속도로 문제를 풀고(자율 진행), **서로 다른 모둠원 여럿**이 맞혀야 모둠의 "영차!"가 준비된다. 돌아가며 맡는 **기수**가 모둠과 신호를 맞춰 "영차!"를 누르면 모둠이 줄을 당긴다.
파일: `server/modes/tug.js` · `public/js/modes/tug.js` · `public/css/tug.css` · `tests/tug.test.mjs`

## 규칙
- **줄 위치** r: −100 ~ 100 (0 = 가운데). 왼쪽(−) = 우리 반·청군, 오른쪽(+) = 도깨비 팀·홍군. 판마다 가운데에서 시작.
- **영차 게이지 (협력의 핵심)**: 정답을 맞히면 그 학생이 모둠의 "이번 박자"에 들어간다. 같은 학생은 한 박자에 **한 번만** 센다(여러 번 맞혀도 1명).
  - 필요 인원 `need = max(2, ceil(접속 모둠원 × 0.5))`, 접속 모둠원이 1명이면 1. (2~4명 → 2, 5~6명 → 3)
  - 서로 다른 인원 ≥ need 이면 "영차 준비". 준비된 뒤에도 더 맞히면 박자에 더해진다(기다리면 힘이 커지지만 자동 영차 시간이 흐른다).
- **기수**: 모둠마다 한 명. 영차를 누를 수 있는 사람은 기수뿐(다른 친구 화면엔 "기수: ○○"). 영차가 끝나면 다음 모둠원에게 넘어간다(들어온 순서대로 돌림). 기수가 나가면 바로 다음 친구에게.
- **자동 영차**: 준비된 뒤 6초 안에 기수가 안 누르거나 기수가 자리에 없으면 저절로 당긴다 (아무도 막히지 않게).
- **힘** = 서로 다른 기여 인원, 접속한 모둠원 **모두**(2명 이상)가 보태면 **한마음 +1**.
- **움직임** = 힘 × 2.2 × 100 / (c0 × 접속 인원 × 한 판 초). 반 크기와 상관없이 같은 느낌.
- **도깨비 팀**: 1초에 100/한 판 초 만큼 꾸준히 당긴다(±30% 출렁임). 혼자면 한 판 시간에 끝까지.
- **판 승패**: 줄 가운데가 한쪽 끝(±100)에 닿으면 바로, 아니면 시간이 끝날 때 줄이 더 가까운 편. 정확히 가운데면 비김.
- **판 수**: 1판, 또는 3판. 우리 반 방식은 **세 판을 모두** 하고 "우리 반이 세 판 중 몇 판"을 알려 준다(2판 이상이면 우리 반 성공). 청홍전은 **먼저 두 판**.
- 판 사이: 결과 3.5초 → 3-2-1(3초) → 시작. 3-2-1 동안에도 문제를 풀어 박자를 모을 수 있다(당기기는 시작 뒤).
- **틀리면** 해설을 보고 다음 문제. 벌칙·탈락 없음.

### 청군 vs 홍군 (선택, "협력적 팀 경쟁")
짝수 번째 모둠(청룡·봉황·백호) = 청군, 홀수 번째(주작·해치·현무) = 홍군. 도깨비 없이 두 편이 서로 당긴다. 움직임 = 힘 × 2.0 × 100 / (c0 × **그 편** 접속 인원 × 한 판 초) → 편 인원이 달라도 공평. 모둠이 1개뿐이면 2개로 다시 나눈다.

## 숫자 근거 (모의 실험, `tests/tug.test.mjs` 첫 검사와 같은 방식)
25명·6모둠, 1분 4문제·정답률 70%, 기수 85%가 0.5~3초 안에 누름, 150번 평균:
| 상황 | 결과 |
|---|---|
| 보통 반, 1분 30초 판 | 150/150 승리, 대부분 약 75초에 끝까지 (60초 판 52초 · 2분 판 95초) |
| 조금 느린 반 (1분 3문제·60%) | 149/150 승리 (시간 끝에 위치로) |
| 느린 반 (1분 2.5문제·55%) | 61/150 승리 → "노력해야 이긴다" |
| 12명·3모둠 / 30명·6모둠 | 둘 다 승리, 약 71초 / 78초 |
| 기수가 하나도 안 누름 | 자동 영차로도 승리 (약 70초) |
| 청홍전 같은 실력 13 대 12명 | 42% 대 58% (거의 반반) |
c0 = 0.040 (보통 반 한 사람의 초당 힘, 위 실험에서 측정).

## 연구 원리 적용 (docs/COOP_DESIGN.md)
1. 전원 대 게임: 기본은 우리 반 vs 도깨비. 청홍전은 선택 설정, 이름도 "협력적 팀 경쟁".
2. 서로 다른 모둠원 n명: 한 명이 아무리 맞혀도 혼자서는 영차가 안 된다(검사로 확인). 한마음 보너스로 "모두"를 북돋음.
3. 기능 역할 돌림: 기수는 힘을 더 주지 않고 "신호 맞춰 누르기"만. 영차마다 다음 친구에게.
4. 개인 순위 없음: 화면엔 모둠 게이지와 "이번 박자에 보탠 친구"(밝은 아바타)만. 결과는 `noRank`.
5. 탈락·벌칙 없음, 오답은 해설 뒤 계속.
6. 앱은 타이밍·기억만, "지금 당길까 / 다 모일 때까지 기다릴까"는 모둠이 말로 정한다.

## 메시지 (서버 → 화면, `m {type,data}`)
- `round` {style, rounds, round, phase('count'|'pull'), wins, sides, r, countLeft, timeLeft, seconds, teams[{ti,side,id,name,color,emoji}]}
- `rope` (200ms마다, 바뀐 것만) {r, timeLeft, phase, g:[게이지]}
- `board` (1초마다 전체) = round 내용 + g(모든 모둠 게이지) + online
- `mine` (나만) {ok, fresh(이번 박자에 처음), contrib, g}
- `pull` {ti, side, strength, distinct, need, all, auto, by, r}
- `roundEnd` {round, rounds, winner(0|1|null), how('line'|'time'), wins, r, sides, final}
- `result` {style, wins, rounds, played, winner, classWin, text, sides} → 3초 뒤 `end`
- 게이지 g: {ti, n, need, on, ready, all, done:[pid], gisu, gisuName, pulls, autoLeft}
- 시간은 모두 남은 ms (기기 시계가 달라도 됨). 학생 → `s:mode {type:'pull'}` (기수·준비·당기는 중일 때만, 아니면 `{error}`).

## 연구 기록 (`api.event`)
`role`(기수 맡음: team, role:'gisu', round, reason start|rotate|away) · `shared`(영차마다: team, distinct, need, all, strength, auto, round, online; pid = 그때 기수) · `round`(판 결과: winner, how, r, wins, strength) · `classGoal`(우리 반 방식 끝) / `teamGoal`(청홍전 끝).

## 결과 (`ranking`)
모두 `rank: 1`, 모둠 순서로 정렬. `score` = contrib. `extra`: noRank, team, teamName, contrib(영차에 쓰인 내 정답), teamContrib, share, classWin(청홍전은 우리 편 승리), roundsWon, rounds, side, style, gisuPulls, correct, answered.
