## 원리 (모든 전통놀이 모드가 지킨다)
1. **전원 대 게임 (D8 S3).** 우리 반·모둠은 게임(도깨비)과 겨룬다. 학생끼리 직접 경쟁은 피한다 (Clark 2016: 단독 경쟁 g=−.06, 협력적 팀 경쟁 .22). 모둠 대항은 선택 설정으로만, "협력적 팀 경쟁"이라고 부른다.
2. **개인 기여가 공동 진행의 필요 조건.** 진행은 "정답 수"가 아니라 **서로 다른 모둠원 n명**의 정답으로 일어난다. 같은 학생의 중복 정답은 그 박자·라운드 안에서 한 번만 센다. 점검 질문: *한 명이 빠지면 깰 수 없는가?*
3. **역할은 기능 차이로만, 돌아가며.** 자원(점수·힘) 격차를 주는 역할은 금지. 라운드마다 다음 모둠원에게 넘어간다 (예: 기수 = 모둠과 신호를 맞춰 "영차" 누르기, 던지는 사람 = 윷 던지기).
4. **개인 순위·리더보드 없음.** 학생 화면과 TV에는 "모둠 진행 + 내가 보탠 몫(기여 아이콘)"만. 결과는 등수 대신 "모둠에 보탠 몫"과 성찰.
5. **탈락 없음, 다시 도전.** 틀리면 해설을 보여 주고 바로 다음 문제. 들켜도 한 걸음 뒤로만.
6. **앱은 timing · randomising · remembering · 비공개 정보, 의논은 책상에서.** 말 옮기기·길 고르기는 모둠이 말로 의논하고 화면은 확인 순간에만.
7. **앱 = 교사의 눈.** 교사 화면에 알림(정체 4분, 연속 오답 2, 기여 적음 0.15, 독주 0.5) — 셸이 공통으로 계산한다. 차시당 12건 이하로.
8. **성찰.** 게임이 끝나면 학생이 "오늘 내가 모둠에 보탠 몫"을 고른다 (셸 공통).

## 공통 계약 (server.js api)
- `api.ensureTeams(n)`: 대기실 모둠을 그대로 쓰거나 n개로 다시 나눈다 (n=0 이면 대기실 모둠 수, 그것도 없으면 4로). `api.teams()` → `[{id, name, color, emoji}]` (청룡·주작·봉황·해치·백호·현무).
- `api.event(type, pid, data)`: 연구용 기록 → 교사 브라우저 → 기록 파일 `events`. 남길 것: `shared`(공동 진행: team, distinct 인원, needed), `round`, `role`(누가 어떤 역할), `choice`(갈림길 선택·거절), `caught`(무궁화 들킴), `help`, `teamGoal`, `classGoal`.
- `ranking(room)` 은 셸 때문에 여전히 배열을 돌려주되 `extra` 에 `{ noRank: true, team, teamName, contrib, teamContrib, share, classWin }` 를 넣는다. `contrib` = 이 학생 정답 중 공동 진행에 쓰인 수, `share` = contrib / teamContrib. 셸은 `noRank` 면 등수 대신 기여 화면을 보여 준다. `score` 는 contrib.
- 그림: `public/assets/trad/` (team_<id>.png 모둠 문장, sulae_back/look.png, rope.png, yut_*.png, mal_<color>.png, bg_madang.jpg, hanji.jpg) — 만들고 있는 중이므로 항상 이모지·CSS 대체.
